# The scaling table (RCP-004; PP4.7): what RecipeScaler shows a reader for lines bloggers really write, at 1/2x, 2x, 3x,
# and two custom servings (3/4 and 5/4: 3 or 5 servings of a recipe for 4).
#
# Each case is a "> " line, the ingredient exactly as written (escapes as in ingredient-lines.txt), then one line per factor,
# in this order: 1/2, 2, 3, 3/4, 5/4. Each says:
#   <factor> = "<the line the reader sees>"       the line was scaled; ", rounded" when the amount shown is not exact
#   <factor> = as written                           nothing to scale, or the amount rounds back to the blogger's own
#   <factor> = as written, unscaled <reason>        not scaled, and flagged: unparsed or other-amounts
# At 1x every line is as written; ScalingCorpusTests proves that for the whole parser corpus.
#
# Every expectation here was read and approved by hand. Nothing rewrites this file: when the scaler's answer for a line
# changes on purpose, that line is edited, and the change says why (CLAUDE.md: golden files are never re-approved in bulk).
# Pinned on purpose: an item's own words never change ("1 eggs", "2 onion"), an abbreviation is never inflected ("1 lbs"),
# a size written after the unit ("1 can (15 oz) black beans") is read as another amount, and so is a size whose fraction
# would join a new whole amount ("2 ½-inch" reads as 2½).
